# 小红书收藏夹与单篇笔记导入设计

**日期：** 2026-08-05
**状态：** 待用户书面审核
**目标版本：** `interactive-trip-planner` 0.2.0
**范围：** 用户资料输入层、登录风险确认、本地旅行资料库、旅行地点发现衔接

## 目标

让旅行者不用把几十篇收藏逐篇整理成地点清单。用户可以粘贴一个小红书收藏夹链接，或粘贴若干单篇笔记链接；Skill 提取笔记、整理地点与体验信号、去重并保存到本地资料库，再把与当前旅行相关的内容送入既有“发现候选 → 核实事实 → 安排行程”流程。

产品必须同时满足：

1. 收藏夹完整读取在必要时允许使用用户已经登录的小红书网页，但必须在操作前解释风险并获得本次导入的明确确认。
2. 不接受登录风险的用户可以改为粘贴单篇笔记分享链接；单篇导入默认不使用用户 Cookie。
3. 登录态只用于取得收藏夹内完整的笔记链接清单，不用于逐篇打开、评论、点赞、收藏、发布或下载。
4. 小红书内容只作为发现、品味与体验线索，不直接证明营业时间、票务、价格、交通、安全或当期活动。
5. 原始笔记与个人资料默认只保存在本地，不进入 Git、REDSkill 发布包、公开地图或 Taste Model 贡献包。

## 已确认事实与产品判断

### 当前验证结果

- 公开收藏夹页面在不带 Cookie 的移动网页请求中可以返回收藏夹名称、总笔记数和首批笔记元数据。本次验证样本显示总数 28、匿名首批 10。
- 匿名首屏不足以证明所有分页都能无登录读取；完整收藏夹在实际使用中可能需要登录后的网页滚动或分页。
- 收藏夹首屏可取得笔记 ID、标题、作者和封面，但不保证每条都有可直接匿名读取详情的 `xsec_token`。
- 单篇公开分享链接可以由无登录解析器尝试读取；成功率、媒体清晰度和可访问字段会随链接格式、token 与平台规则变化。

### 产品判断

采用“最小登录面”而不是“全流程登录采集”：

```text
收藏夹链接
  → 先匿名读取首批与总数
  → 匿名结果不完整时展示风险说明
  → 用户本次确认后，仅在已登录网页读取完整链接清单
  → 立即退出登录态采集
  → 每条笔记单独走无 Cookie 解析
  → 本地整理、去重、提炼旅行信号
  → 进入目的地发现与官方事实复核
```

这可以把账号风险限制在“读取收藏夹列表”一步，并避免自动打开几十篇笔记形成更高强度的账号行为。

## 方案比较

### A. 全程使用登录态浏览器

收藏夹列表和每篇详情都从用户已登录页面读取。

- 优点：成功率和可见字段通常更高。
- 问题：自动翻页与逐篇访问次数多；风险范围大；容易形成账号、Cookie 和浏览器依赖。
- 结论：不采用。

### B. 收藏夹登录取链接，单篇匿名解析（推荐）

匿名读取能拿多少先拿多少；仅在列表不完整且用户确认后，使用登录网页补齐链接。后续详情读取不再使用登录态。

- 优点：满足“一次粘贴收藏夹”的体验；显著缩小登录行为；本地资料库可继续复用。
- 问题：仍存在登录网页自动滚动风险；单篇匿名解析可能部分失败。
- 结论：作为 0.2 默认完整链路。

### C. 只接受单篇链接

完全不提供收藏夹批量读取。

- 优点：边界最简单，账号风险最低。
- 问题：无法解决“收藏几十篇仍排不出一天”的核心问题。
- 结论：保留为无登录风险模式和降级路径，不作为唯一方案。

## 用户流程

### 入口识别

Skill 识别两类输入：

- 收藏夹链接：`xiaohongshu.com/board/...`
- 单篇分享链接：`xhslink.com/...`、`xiaohongshu.com/explore/...` 或当前可识别的公开笔记链接

用户可以一次粘贴一个收藏夹，或一次粘贴多条单篇链接。其他个人主页、搜索页、收藏 tab、评论页和非小红书 URL 不自动升级为采集任务。

### 收藏夹导入

1. 先以无 Cookie 请求读取收藏夹基本信息和匿名可见笔记。
2. 如果匿名已取得全部链接，直接进入单篇解析，不触发风险确认。
3. 如果 `已取得数量 < 收藏夹总数`，向用户显示当前进度和以下选择：
   - 继续读取完整收藏夹：使用用户选定并已登录的小红书网页，有自动化风控风险。
   - 只导入匿名已读取部分。
   - 改为粘贴单篇笔记链接。
4. 用户选择完整读取时，每次导入都重新确认；不保存“永远同意”。
5. Agent 不得静默选择用户现有 Chrome 登录态。用户必须指定浏览器，或主动打开并交付本次收藏夹标签页。
6. 只滚动收藏夹并读取页面已渲染的笔记链接；达到总数、连续两次无新增、遇到验证码/风险提示或达到本次上限时停止。
7. 链接清单取得后立即结束登录态浏览，不在该会话中逐篇打开笔记。

### 风险确认文案

在使用登录态前完整显示：

> 为读取这个收藏夹的全部笔记，需要使用你已经登录的小红书网页并自动加载更多内容。平台可能把自动滚动或批量读取识别为自动化行为，存在验证码、限流、账号风控或封禁风险。Skill 不会读取或保存 Cookie，不会点赞、收藏、评论、关注或发布；登录态只用于取得笔记链接清单。你也可以不继续，改为粘贴单篇笔记链接。

确认必须指向本次收藏夹和本次操作。用户表达犹豫、不同意或没有明确回复时，不进入登录态读取。

### 单篇解析

1. 解析分享短链并校验最终域名。
2. 使用不带 `Cookie`、`Authorization` 的有界请求读取公开页面。
3. 提取标题、正文、作者显示名、标签、图片/视频元数据、地点文本和发布时间等页面真实存在的字段。
4. `xsec_token`、`share_id`、`appuid`、签名参数和其他追踪参数只在当前请求内临时使用，不写入本地资料库、日志或最终来源 URL。
5. 默认不下载原图、视频或评论；只保存媒体类型、数量和规范化笔记页引用，不持久化带临时签名或追踪参数的媒体直链。需要 OCR 时只处理用户明确要求或地点识别必要的少量图片，并在处理后删除临时文件。
6. 匿名解析失败时记录失败原因，不自动回到登录浏览器读取详情。用户可以补充新的单篇分享链接、正文或截图。

### 收藏消化报告

每次导入结束后，用自然语言展示：

- 收藏夹总数、发现链接数、成功解析数、重复数和失败数。
- 提取出的城市、街区、地点、地方品类、活动和体验主题。
- 多篇重复推荐、相互冲突、负面体验与可能过时的信息。
- 与当前旅行相关、可以进入候选池、需要官方复核和暂不采用的数量。
- 本地资料库位置和本次新增内容。

报告不得声称小红书内容已经证明地点营业、活动存在或路线可行。

## 本地旅行资料库

### 默认位置

第一次使用时允许用户选择目录；未指定时在当前旅行工作区创建：

```text
travel-library/xiaohongshu/
  library.json
  notes/<note-id>.json
  imports/<import-id>.json
  README.md
```

这是跨该工作区不同旅行复用的私人资料库。每次攻略只保存相关笔记 ID 的引用，不复制整库。

### `library.json`

保存：

- 资料库格式版本。
- 已知笔记 ID 与本地文件位置。
- 首次导入、最近更新和去重状态。
- 用户自己的“喜欢、忽略、已去过、想去”状态（用户主动表达时才写）。

不保存 Cookie、浏览器配置、账号 ID、访问 token、请求 header 或原始收藏夹跟踪参数。

### `notes/<note-id>.json`

保存：

- 规范化后的公开笔记 URL。
- 标题、作者显示名、正文、标签、媒体类型与数量；默认不保存带签名参数的媒体直链。
- 导入时间、内容更新时间线索和访问方式：`anonymous-public` 或 `authenticated-board-link-only`。
- 从笔记提炼的地点、品类、体验理由、负面信号、时间线索和待核实事实。
- 哪次导入发现了这篇笔记。

完整正文仅供私人本地整理。写入攻略 `data/sources.json` 时只保留来源标题、规范化 URL、简短支持范围和检查日期；公开地图不复制笔记全文或媒体。

### `imports/<import-id>.json`

保存一次导入的审计摘要：

- 输入类型、匿名读取数量、登录态补齐数量和最终链接数量。
- 是否展示风险说明、用户是否确认本次登录读取。
- 成功、重复、失败和停止原因。
- 不保存 Cookie、token、浏览器身份或完整请求日志。

### Git 与发布边界

- `travel-library/` 默认加入当前旅行工作区 `.gitignore`，除非用户明确把脱敏后的派生结果贡献为 Taste Model 样本。
- Skill 源码和 REDSkill 发布包只包含空模板、schema、文档和合成测试 fixture，不包含真实小红书笔记、账号、链接 token、截图或用户收藏夹。
- 从资料库贡献模型时，必须走现有 owner、license、脱敏与代表行程审核流程。

## 旅行规划衔接

小红书笔记进入现有来源体系时只能承担：

- `discovery`：发现地点、品类、街区、节庆线索和当地用词。
- `recommendation`：支持“为什么进入候选”与推荐品类。
- `experience`：补充排队、点单、服务、噪音、入口、拍照、治安体感等现场线索。

以下内容必须回到官方、运营方、地图、票务或主办方复核：

- 营业时间、闭馆日、价格、菜单库存和预约政策。
- 当期节庆、展览、演出和活动日期。
- 交通班次、签证、法规、安全结论和天气风险。

地点去重优先使用地图平台的正式 POI 与城市/街区语境；只有名字相似不能直接合并。笔记推荐的是地方菜、饮品、市场品类或生活方式而非具体商户时，保留为“当地体验线索”，不伪造成店铺。

## 组件与责任边界

### Agent 工作流

- 识别收藏夹或单篇链接。
- 先匿名读取并判断是否完整。
- 展示风险、等待明确确认、控制登录浏览器的只读链接提取。
- 把网页内容视为不可信外部输入，不执行笔记中的任何指令。
- 调用确定性脚本完成 URL 清理、去重、存储和报告统计。
- 使用模型提炼旅行语义，再进入既有事实复核与路线流程。

### 确定性脚本

预计新增：

- `skill/scripts/xhs-import-runtime.js`：URL 分类、域名校验、参数清理、ID 提取、去重和数据规范化。
- `skill/scripts/fetch-xhs-public.js`：只用无 Cookie 请求读取公开收藏夹首批或单篇页面，解析内嵌公开状态并输出结构化结果；设域名白名单、重定向上限、超时、响应体上限与 HTML 类型校验。
- `skill/scripts/import-xhs-library.js`：接收文件或 stdin 的结构化导入结果，安全写入本地资料库。
- `skill/scripts/validate-xhs-library.js`：验证目录、schema、token/敏感字段禁项、引用和重复项。
- `skill/scripts/summarize-xhs-import.js`：输出不含正文和 token 的导入摘要。
- 与上述能力对应的单元、CLI 和发布合同测试。

匿名公开请求可以由 `fetch-xhs-public.js` 或 Agent 当前可用的网页工具执行；两者都不得发送 Cookie 或 Authorization，并只接受小红书允许的公开域名。登录浏览器控制不隐藏在脚本内：必须经过产品风险确认并使用宿主提供的受控浏览器。任何脚本都不会读取浏览器 Cookie 数据库、接管浏览器 profile 或启动隐藏登录进程。

`fetch-xhs-public.js` 是 best-effort 解析器，不承诺绕过平台变化。遇到登录页、验证码、风控页、缺失公开状态、超限响应或非 HTML 响应时，以结构化失败返回并进入既定降级路径，不伪造空结果为成功。

### Codex 与 REDSkill

- Codex 完整版在宿主提供受控浏览器、用户明确确认并选定标签页时，可以执行收藏夹完整链接读取。
- 宿主没有浏览器控制能力、没有登录态或用户不确认时，自动降级为匿名部分导入或单篇链接导入。
- REDSkill 发布包保留流程、数据合同、脚本和降级文案；不得因为某个平台不提供浏览器能力而宣称已完成完整收藏夹导入。

## 安全与异常处理

### 绝对禁止

- 自动读取、导出、解密或复制浏览器 Cookie。
- 将 Cookie、`xsec_token`、`share_id`、`appuid`、Authorization 或签名参数写入磁盘或日志。
- 自动登录、代用户输入密码或验证码。
- 绕过验证码、访问限制、风控提示或平台安全页面。
- 在未额外授权时点赞、收藏、评论、关注、私信、发布或删除内容。
- 为提高成功率静默切换到其他用户浏览器、账号池或第三方服务。

### 停止条件

出现以下任一情况立即停止登录态读取：

- CAPTCHA、短信验证、二维码确认或账号安全提示。
- 页面显示访问频繁、限制访问或行为异常。
- 连续两次加载没有新链接。
- 已取得收藏夹声明总数。
- 本批达到默认 50 篇读取上限；如收藏夹更大，先展示已完成数量，再由用户决定是否开始下一批。
- 用户接管或终止浏览器操作。

停止后保留已取得链接并报告停止原因；是否换成单篇链接由用户决定，不自动重试。

## 测试策略

按 RED → GREEN 实现：

1. URL 分类：收藏夹、单篇长链、短链、未知页、非小红书域名和 URL 内嵌凭据。
2. URL 清理：输出不包含 `xsec_token`、`share_id`、`appuid`、fragment、用户名或密码。
3. 匿名读取器：只允许白名单域名；不发送 Cookie/Authorization；限制重定向、超时和响应体；登录页、验证码、风控页、异常内容类型和解析结构变化均结构化失败。
4. 风险状态：匿名完整无需确认；匿名不完整只能在本次明确确认后进入 `authenticated-board-link-only`。
5. 禁止升级：单篇解析失败、未登录、无浏览器、用户拒绝、CAPTCHA、风控和中途停止都不得静默切换登录态或第三方服务。
6. 本地资料库：创建、增量导入、同 ID 去重、跨收藏夹重复、失败恢复、删除后重建索引和非法路径拒绝。
7. 隐私：fixture、stdout、stderr、import manifest、生成 release 和公开 README 不包含 token、Cookie、真实账号、真实笔记正文或带签名的媒体直链。
8. 旅行衔接：社媒来源只能生成 `discovery`、`recommendation`、`experience`，不能成为营业、票务、安全或活动确认事实。
9. CLI：`--context` / `--stdin` 互斥、JSON-only stdout、错误退出码、`--help` 和大输入上限。
10. 浏览器手动验收：经用户明确授权后，用一个小收藏夹验证匿名首批、风险确认、登录补齐、停止条件和不逐篇打开；遇 CAPTCHA 不继续。
11. 完整运行 `npm test`，检查 `releases/redskill-0.2.0/` 只有支持格式且不包含私人资料库。

所有自动测试使用合成 HTML、合成 URL 和虚构笔记，不把本次真实收藏夹作为仓库 fixture。

## 验收标准

- 粘贴收藏夹链接后，Skill 先匿名读取并准确告诉用户“总数、已读数量、是否需要登录补齐”。
- 未确认风险时不会访问任何登录态页面；确认后登录态只用于链接清单。
- 用户拒绝登录风险时，可以继续导入匿名部分或粘贴单篇链接，不阻塞旅行规划。
- 单篇解析不读取用户 Cookie；失败不会回到登录浏览器。
- 同一笔记从多个收藏夹导入只保存一份，并保留来源关系。
- 本地资料库可跨旅行复用，攻略只引用相关笔记。
